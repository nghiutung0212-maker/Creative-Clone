# 创意分身 Skill — 测试用例

> 本文档由 F · 验收部产出，给出覆盖 3 个不同场景的完整测试用例，并附「实跑一轮」的 6 步闭环记录。
> 判定依据：`quality_standards.md`（评分标准）；对照 C 部 `bad_topic_blacklist.md`、`output_template.md`。

## 1. 用例总览

| 用例 | 场景 scene_id | 用户设定 | 关键难点 |
|------|--------------|---------|---------|
| 用例 1 | academic_paper | 历史学本科生，兴趣电子游戏，想在公选课交作业 | 跨界碰撞 + 学术严谨与趣味并存 |
| 用例 2 | short_video | 自媒体新手，想做知识类内容，没团队 | 冷启动 + 单点信息 + 合规 |
| 用例 3 | event_planning | 学生社团，预算有限，想做创意活动 | 零预算 + 安全合规 + 可执行 |

每个用例包含：输入（画像 + 问卷回答）、预期输出（四要素 + 场景补充）、验收检查点（对照评分标准）。

## 2. 用例 1：论文选题（academic_paper）

### 2.1 用户设定

历史学本科生，兴趣电子游戏，想在公选课交一份有网感的课程论文。

### 2.2 输入

**画像快照（profile_snapshot）**

```json
{
  "base": {
    "language": "zh-CN",
    "backgrounds": ["历史学（本科）"],
    "interests": ["电子游戏"],
    "resources": ["学校图书馆数据库", "每周约 12 小时"]
  },
  "preferences": [
    { "key": "tone_preference", "value": "可带一点趣味", "source": "explicit" }
  ]
}
```

**问卷回答（answers）**

| 字段 | 回答 |
|------|------|
| discipline | 历史学（中国近现代史方向） |
| level | 课程论文 |
| research_type | 案例/文本分析 |
| length | 3000–5000 字 |
| cycle | 两周内 |
| tone | 可带一点趣味 |
| interests | 电子游戏（《文明》系列） |
| resources | 学校图书馆数据库、每周约 12 小时 |
| hard_constraints | 公选课作业，要求有明确问题意识与文献支撑 |
| excludes | 不想做纯文献综述 |

### 2.3 预期输出

按 `academic_paper` 配置输出 N 个候选，每个严格含四要素，并追加「建议篇幅、建议研究方法、关键词与检索数据库、伦理审查要求」：

1. **选题标题**：`《{具体问题}——以{研究对象}为例》`，对象与限定词齐全、问题可证伪；
2. **为什么适合你**：引用画像真实条目（历史学背景、电子游戏兴趣、公选课基调、资源），不得编造；
3. **三个切入角度**：互不重叠、可直接动手；
4. **风险提醒**：覆盖可行性 / 难度 / 伦理合规；
5. **场景补充**：建议篇幅、研究方法、关键词与数据库、伦理审查要求。

### 2.4 验收检查点

- [ ] 四要素齐全，标题为可证伪的具体问题
- [ ] 「为什么适合你」引用 ≥3 条画像条目且逐条说明用途
- [ ] 不出现黑名单 5 类任一类型（重点防「概念堆砌」「范围过大」）
- [ ] 方法与资源匹配（图书馆数据库 + 12 小时，无需大型系统）
- [ ] 基调贴合「可带一点趣味」但论证严谨（D5）
- [ ] 按 `quality_standards.md` 打分：总分 ≥ 18，各维度 ≥ 3，黑名单零命中

## 3. 用例 2：短视频选题（short_video）

### 3.1 用户设定

自媒体新手，想做知识类内容，没团队，一人一部手机。

### 3.2 输入

**画像快照**

```json
{
  "base": {
    "language": "zh-CN",
    "backgrounds": ["大学生"],
    "interests": ["学习方法", "效率工具"],
    "resources": ["一人一部手机", "零预算"]
  },
  "preferences": [
    { "key": "hook_style", "value": "反常识", "source": "explicit" }
  ]
}
```

**问卷回答（answers）**

| 字段 | 回答 |
|------|------|
| account_domain | 大学生知识区 |
| platform | 抖音 |
| audience | 大学生 |
| duration | 30–60 秒 |
| form | 真人口播 |
| account_stage | 零粉冷启动 |
| hook_style | 反常识 |
| goal | 涨粉 |
| red_lines | 不制造焦虑、不引战 |

### 3.3 预期输出

按 `short_video` 配置输出，标题为「钩子文案 + 选题标题」，四要素 + 场景补充（前 3 秒钩子、建议时长、拍摄形式、标签与封面建议）：

1. 选题能在 60 秒内讲清**单一观点**；
2. 前 3 秒有反常识钩子；
3. 一人一部手机可完成（无团队、无道具、无外景）；
4. 观点有常识性依据，不夸大、不承诺效果。

### 3.4 验收检查点

- [ ] 四要素齐全，标题带钩子
- [ ] 一条视频只表达一个信息点（符合 `constraint_list`）
- [ ] 无需团队/预算即可拍摄（D3 可行性）
- [ ] 不触碰平台违规/引战/虚假宣传（D5 + 场景 `exclusion_rules`）
- [ ] 匹配「零粉冷启动 + 大学生受众」的画像（D4）
- [ ] 按评分标准打分通过（总分 ≥ 18，各维度 ≥ 3，黑名单零命中）

## 4. 用例 3：活动策划（event_planning）

### 4.1 用户设定

学生社团，预算有限，想做创意活动。

### 4.2 输入

**画像快照**

```json
{
  "base": {
    "language": "zh-CN",
    "backgrounds": ["某高校学生社团"],
    "interests": ["桌游", "创意市集"],
    "resources": ["校内免费场地", "社团成员 8 人", "预算 500 元以内"]
  },
  "preferences": [
    { "key": "style_preference", "value": "轻松玩梗", "source": "explicit" }
  ]
}
```

**问卷回答（answers）**

| 字段 | 回答 |
|------|------|
| organizer | 某高校桌游社 |
| event_type | 校园社团活动 |
| audience | 在校大学生 30–50 人 |
| budget | 500 元以内 |
| cycle | 一周左右 |
| goal | 招新 |
| venue | 校内免费教室（已确定） |
| style | 轻松玩梗 |
| constraints_excludes | 需校方报备、不能有明火、参与者可能有忌口 |

### 4.3 预期输出

按 `event_planning` 配置输出，标题为「活动主题名 + 活动类型策划方案」，四要素 + 场景补充（预算分配、关键流程时间线、人员分工、物料清单、应急预案）：

1. 方案在预算（500 元内）、人力（8 人）、周期（一周）、场地（校内教室）内可执行；
2. 有明确活动目标（招新）与衡量方式；
3. 参与门槛低、兼顾不同性格与身体条件；
4. 安全合规，有应急预案。

### 4.4 验收检查点

- [ ] 四要素齐全（活动场景以「方案」形态呈现四要素）
- [ ] 低预算下可执行，不采购贵重物料（D3）
- [ ] 覆盖招新目标与留存/转化设计（场景 `skip_logic`）
- [ ] 无安全隐患、无明火、尊重忌口（D5 + `exclusion_rules`）
- [ ] 有应急预案（天气/设备/人数/突发）（场景 `constraint_list`）
- [ ] 按评分标准打分通过

## 5. 附录：实跑一轮（用例 1 · 6 步闭环完整记录）

> 实跑日期 2026-10-13；运行环境为本地离线，未挂载 WebSearch。以下按 SKILL.md 主流程逐步执行并如实记录，含一处**降级路径**的实测。

### Step 1 场景选择

用户描述「公选课论文选题」→ 命中 `academic_paper` 触发词 → 加载场景配置 → JSON 语法与 7 字段校验通过 → 进入 Step 2。

### Step 2 场景化问卷

分 4 轮作答（答案见 2.2 节）；「课程论文」触发跳转：跳过期刊/基金级别问题，保留篇幅与周期问题。

### Step 3 对话式补充

追问画像缺口（3 个）：① 是否想在公选课里玩点网感 → 是，但论证要严谨；② 对反常识角度的容忍度 → 高；③ 是否有可用的玩家样本渠道 → 有同校同学。未授权本地读取 → 保持轻量模式，跳过本地文件读取。

### Step 4 三引擎

**引擎 A · 饱和扫描**：环境无 WebSearch，按 `on_no_evidence = mark_unsure` 走知识库兜底，`evidence.real_time = false`，结论仅作提示性规避：

- 「罗马帝国衰亡原因」→ 经典议题、积累极厚，`hot`（提示规避，不写硬黑名单）；
- 「游戏媒介对大众历史认知的影响（以《文明》为对象）」→ 交叉方向实证少，`gap`；
- 饱和方向与黑名单命中：无（因未实时检索，不写入硬性黑名单）。

**引擎 B · 跨界碰撞**：核心域「历史学（罗马帝国）」× 兴趣域「电子游戏（《文明》）」→

- 候选 1（成立）：《从〈文明〉系列游戏看大众对罗马帝国的认知偏差——以某高校 30 名非历史专业本科生为例》，`why_link` = 同一对象在史书与游戏中的呈现差异可比较、可证伪；
- 候选 2（反例，剔除）：《元宇宙背景下大模型赋能罗马史教学的路径研究》→ 抽掉热词问题不成立，`filtered_out`。

**引擎 C · 自我批判审稿**（`quality_gate = pass_all`）：

- 候选 1：C1–C6 全过（对象明确 / 问题可证伪 / 文本分析 + 问卷访谈方法匹配 / 在资源周期内 / 游戏媒介视角有增量 / 贴合「可带一点趣味」基调）→ `pass`；
- 候选 2：C2、C5 不通过，`fatal_flaw = concept_stack` → `reject`。

### Step 5 输出（通过闸门的候选，四要素）

```text
选题 1
【选题标题】
《从〈文明〉系列游戏看大众对罗马帝国的认知偏差——以某高校 30 名非历史专业本科生为例》
【为什么适合你】
· 历史学（本科）背景 —— 能提供罗马史的「基准叙事」作偏差参照；
· 兴趣：电子游戏（《文明》）—— 熟悉游戏机制，能拆解其罗马设定；
· 公选课 + 可带一点趣味 —— 题目自带网感、课堂讨喜，论证仍可严谨；
· 资源：图书馆数据库 + 每周 12 小时 —— 支撑文本分析与小样本问卷。
【三个切入角度】
1. 设定切入：提取《文明 VI》罗马科技树/政体/领袖/奇观，标记其对罗马兴衰的简化处理；
2. 受众切入：对 30 名非历史专业玩家问卷 + 5 人访谈，测玩游戏前后认知差异；
3. 对照切入：将游戏叙事与 2–3 部权威罗马通史对读，提炼被植入的认知框架。
【风险提醒】
· 可行性风险：需控制「是否系统学过罗马史」，样本不足时扩大到相邻两校；
· 难度提醒：难点在把「认知偏差」操作化为可编码题项，需预访谈 + 编码表，约 4–6 周；
· 伦理/合规提醒：涉及人类受试者，需匿名、知情同意、可退出；游戏截图仅作教学/学术评论性引用。
【场景补充】
· 建议篇幅：3000–5000 字
· 建议研究方法：文本/设定分析 + 小样本问卷访谈
· 关键词与数据库：罗马帝国；文明 VI；历史认知偏差 / 中国知网、JSTOR、Google Scholar
· 伦理审查要求：课程论文级别，匿名问卷 + 知情同意即可，无需正式伦理委员会审批
```

### Step 6 反馈迭代（真实脚本执行）

用户对候选 1 标记「最终选中」→ 运行桌面真实脚本：

```text
python3 scripts/update_profile.py --feedback select \
  --topic "《从〈文明〉系列游戏看大众对罗马帝国的认知偏差——以某高校30名非历史专业本科生为例》" \
  --scenario academic_paper --query "历史学本科生，想在公选课交一份有网感的课程论文"
```

沉淀结果（真实输出，节选）：`history` 新增 1 条 `feedback=select` 且含 `chosen_topics`；`signals.selected_topics`、`base.interests` 写入该选题；`preferences` 新增 `selected_topic`（`source=explicit`，`confidence=0.9`）；`stats.select_count = 1`。
